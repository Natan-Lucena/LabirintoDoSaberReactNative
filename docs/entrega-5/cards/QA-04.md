# QA-04 — Homologação em aparelhos

| Campo           | Valor                                                                                                                                  |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Bloco / onda    | F — Qualidade · E5-12 (a última)                                                                                                       |
| Classe / modelo | B · o Victor executa (manual); C (Haiku) para instalar o APK e coletar logs                                                            |
| Estimativa      | M · 1 dia no Android físico; iOS conforme acesso a iPhone/Mac                                                                          |
| Dependências    | QA-08 e QA-03 concluídas; BLD-01 (APK); NOT-02 (push); autorização do usuário; aparelho Android físico; para iOS, iPhone e conta Apple |
| Quem executa    | Victor (Android físico); iOS por quem tiver o aparelho                                                                                 |

## 1. Objetivo

Confirmar no **aparelho real** o que o emulador não mostra: câmera, galeria, áudio, PDF,
compartilhamento, teclado, área segura, desempenho e, nesta entrega, o **push** e o **vídeo**.
Nunca foi feita (pendente desde a Entrega 3).

## 2. Ambiente

- **Android físico**, com dois caminhos: Expo Go (dia a dia) e o **development build** da BLD-01
  (push). Anotar marca, modelo, versão do Android.
- **iOS:** Expo Go da App Store (se a versão da loja suportar o SDK 57) ou build EAS com conta
  Apple. Sem iPhone ou Mac, todas as linhas de iOS ficam **N/A (pendente)**, nunca OK.
- Backend real; `EXPO_PUBLIC_USE_MOCKS=false`.

## 3. Roteiro

Matriz tela × plataforma × recurso nativo do
[09-aparelhos-qa04 da Entrega 3](../../entrega-3/testes/09-aparelhos-qa04.md), acrescida das
linhas da Entrega 5:

| Tela / fluxo                   | Recurso nativo                                         | Android físico | iOS |
| ------------------------------ | ------------------------------------------------------ | -------------- | --- |
| Push (NOT-02)                  | `expo-notifications`, permissão, toque com app fechado | (dev build)    |     |
| Central de ajuda (AJD-01)      | `expo-video`, tela cheia, rotação, som                 |                |     |
| Convite (EQP-01)               | `Share` do sistema                                     |                |     |
| Imprimível (ATV-05)            | `expo-print`, `expo-sharing`                           |                |     |
| Jogos (ATV-04a, ATV-04b)       | toque, áudio da dica (`expo-audio`)                    |                |     |
| Agenda mês (AGE-05)            | `react-native-calendars`, fuso                         |                |     |
| Cadastro pelo convite (EQP-03) | teclado, `KeyboardAvoidingView`                        |                |     |

## 4. Critérios de saída

- Matriz preenchida (OK, FALHA, N/A com motivo, BLOQ) para Android físico (AC-QA-04-01).
- Push recebido e aberto no development build do aparelho; ou pendência registrada com o motivo.
- iOS: preenchido ou explicitamente pendente.

repositório), método, rota e status nas falhas de rede. Registro em
`docs/entrega-5/testes/09-aparelhos.md`.
