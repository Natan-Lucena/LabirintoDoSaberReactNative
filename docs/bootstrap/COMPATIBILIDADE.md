### 9.2 Decisões de implementação (`src/storage/mmkv.ts`)

- **Arquivo mantido como `src/storage/mmkv.ts`** (não renomeado para
  `secure-kv.ts`): a interface pública (`getStorage`, `activateEducator`,
  `getActiveEducatorId`, `clearQueryCache`, `clearSessionFlow`,
  `clearAllForEducator`, `connectStorageToAuth`) não mudou, e manter o caminho
  evita editar os 4 consumidores (`query-persister.ts`, `AppProviders.tsx`,
  `useSignIn.ts`, `session-flow.ts`) só por causa do nome do arquivo — menor
  diff. O nome é um resquício histórico do MMKV; o conteúdo não usa mais MMKV.
- **Um banco SQLite por educador:** `labirinto.<educatorId>.db`, criado por
  `new SQLiteStorage(databaseName)` (API síncrona `getItemSync`/`setItemSync`/
  `removeItemSync`/`getAllKeysSync`/`clearSync`), preservando o isolamento por
  conta exigido pelo G-04.
- **Formato gravado por chave:** `hex(nonce de 12 bytes || ciphertext com a tag
GCM anexada)`. A recomendação original do orquestrador era base64, mas o
  Hermes não expõe `btoa`/`atob`/`Buffer` sem dependência extra; `@noble/ciphers/
utils.js` já traz `bytesToHex`/`hexToBytes` prontos, então o valor é gravado em
  hex para não introduzir mais uma dependência só para a codificação. O
  resultado satisfaz igualmente o AC-EXPO-01-02 (o valor gravado não é legível
  sem a chave).
- **Chave:** continua vindo de `getOrCreateEncryptionKey()`
  (`src/storage/encryption-key.ts`, G-27), sem alteração — já produz uma string
  hex de 64 caracteres (32 bytes), o tamanho exato de uma chave AES-256.
  `hexToBytes` converte direto para os bytes da chave.
- **Valor indecifrável (chave trocada ou dado corrompido):** `getString` captura
  a falha da tag do GCM, trata a chave como ausente (retorna `undefined`, sem
  lançar) e apaga a entrada (`removeItemSync`) para não insistir em decifrá-la de
  novo — AC-EXPO-01-02/G-04.
- **Dados antigos do MMKV:** não há migração. Os arquivos do MMKV nativo (se
  existirem em um dispositivo que já rodou a Entrega 1) ficam órfãos no
  armazenamento do app; o novo backend usa arquivos SQLite com nome diferente
  (`labirinto.<educatorId>.db`) e não os lê. Aceito porque o projeto ainda não
  tem usuários reais (dados fictícios/mock, G-29) nem passou por T-108 em
  produção.
- **Testes:** `expo-sqlite/kv-store` é mockado em memória (`sqliteKvStoreMock`
  em `src/test-utils/mocks.ts`, registrado globalmente em `vitest.setup.ts`),
  substituindo o mock de `react-native-nitro-modules` e os mocks locais de
  `react-native-mmkv` espalhados pelos testes (A-20 deixa de se aplicar: não há
  mais preset automático do `vitest-native` para contornar). A cifra AES-256-GCM
  roda de verdade nesse armazenamento fictício; só o SQLite nativo é simulado.
